Part A

As with all weeks of the National Cipher Challenge 2026, there are two parts to the puzzle. This section relates to Part A.

You may expect the cipher challenge to start fairly straightforwardly, and indeed you would be right. The first thing we can see about this cipher is that it still has its original word structure. That is, the ciphertext words are of variable length and there is punctuation present, suggesting that only the actual letters have changed. This means that we can start to guess what some of the words might be.

For example, we can some single letter words in our ciphertext, such as "U" and "M". Given that the only common English words that consist of a single letter are "a" and "i", we can be reasonably confident that "a" in the original plaintext has been encrypted to either "U" or "M" in the ciphertext. Similarly, we can be confident that "i" in our original plaintext has been encrypted to either "U" or "M" in the ciphertext (whichever one of "U" or "M" that doesn't stand for "a".)

Looking a bit deeper into the ciphertext, and knowing that "the" is the most common word in the English language, we might be able to work out what ciphertext string of letters stands for "the"

To do this, let's look at what three letter words we have in order of their first appearance and, more importantly, let's look at how many of them we have:

Using Python

Now it's quite tedious, and prone to error, to try and find every three-letter word in a long ciphertext, so is there a way that Python could help?

Well, the first thing we might want to do is to create ourselves a constant containing all the letters of the alphabet, as this is likely to come in handy for many reasons when dealing with ciphertexts

ALPHABET = "ABCDEFGHIJKLMNOPQRSTUVWXYZ"

You might notice that we use all capital letters for ALPHABET in the above. This is simply the convention that constants (i.e. variables that don't vary!) get capital letters, whereas you will see shortly that variables (i.e. variables that do vary!) get all lower-case letters.

Another thing to notice is how we have assigned the string ABCDEFGHIJKLMNOPQRSTUVWXYZ to the constant ALPHABET - by using the equals sign (=) and putting the string in double-quotes (") after this. The equals sign is how we always assign a piece of data to a constant, or more commonly a variable, and the double-quotes tell Python that it is a string being assigned. You can in fact use single-quotes just as easily as Python treats them both the same in this case. E.g. ALPHABET = 'ABCDEFGHIJKLMNOPQRSTUVWXYZ' would work just as well.

The next thing we should think about doing is telling our Python script what the ciphertext is. We do this by assigning the string of letters in the ciphertext to a variable, which we may as well call 'ciphertext'.

You can see that we've used the equals sign (=) when we've assigned the string to the variable we've called ciphertext and, in this case, we've used """ either side of the string to let Python know it is a multi-line string.

We shouldn't need such a long piece of text again for a bit but we do still want to set up some extra variables

curr_word = ""
three_letter_words = []

The first of these lines sets up a variable that consists of an 'empty string'. We are going to use this variable to build up each word as we go through the ciphertext one character at a time.

The second variable we are setting up is of a different data type entirely - a list. Lists are enclosed in square brackets and in this case we have set up an empty list. Lists can however be set up with contents. E.g. my_name = ["Bob", "Jones"] is a perfectly valid list. Such a list has "Bob" at element position 0 and at its element position 1 it has "Jones". It may seem odd to start counting at zero but that's just how it is!

Now let's cycle through our ciphertext using a for...loop and build a list of the three letter words as we go.

for letter in ciphertext:
  if letter in ALPHABET:
    curr_word += letter
  else:
    if len(curr_word) == 3:
      three_letter_words.append(curr_word)
    curr_word = ""

This is our most complicated bit of code so let's look at it, one line at a time.

for letter in ciphertext:

This line is how all 'for...loops' start. The 'letter' part of this line is the name for a new variable created just for this loop. It will be assigned a new character of the string for each pass of the loop. Given the first letter of our ciphertext is "Y", letter will be assigned "Y" on the first pass of the loop as the in ciphertext bit is telling python that is the string we are wanting to cycle through.

  if letter in ALPHABET:

This next line checks whether our letter is in our constant ALPHABET, and of course Y is, so Python knows to carry out the next line indented below the colon after the 'if...'.

    curr_word += letter

This line tells Python to 'add' that letter to our 'curr_word' variable. This variable had started as empty (""), so adding "Y" to it makes it now equal "Y". Python has no more lines to consider under that 'if...' and it doesn't need to consider what's under 'else' as "Y" was in the alphabet. Python therefore now has nothing more to do with this particular pass of the loop and so goes back to the start with the next character in our string.

Now the next character this time is "K", so when Python confirms that "K" is in the alphabet, it will add this letter to our 'curr_word' variable. It uses the += combination of characters to do this. This is just a shorthand way of saying curr_word = curr_word + letter. As curr_word currently is "Y" from the first pass of the loop, adding "K" to it makes it "YK".

Now the next pass of the loop is more interesting. The next character Python comes to is the space between "YK" and "PQMD". Now a space is not in our ALPHABET variable and so Python will enter the 'else:' part of the code.

    if len(curr_word) == 3:

This line uses another if to ask if the length of curr_word is 3. It does this using the len function. The double equals sign is not a mistake - if we want Python to evaluate whether one value equals another, we always use ==. (This stops Python getting confused and thinking you want to use an equals sign to assign a value to a variable or constant - the other use of the equals sign that we saw earlier.

Now in this case, the length of "YK" is clearly not 3. It is of course 2, so Python skips the indented line under this if statement.

Instead, Python will go to the line below that, which isn't indented relative to the 'if len(curr_word)...' line.

  curr_word = ""

This line resets curr_word to an empty string before the next cycle of the loop. By this point, we have got to the end of our first word, found it not to have a length of 3, and have therefore not done anything with it

A similar thing will happen for the next word. curr_word will have "P", "Q", "M" and "D" added to it for the next four cycles before the next space is not in the alphabet. Python will find that "PQMD" doesn't have a length of 3, and will also not do anything with this word and will reset curr_word to "".

Similar things will happen with the next words "YMPQYAUEQXXQ", "NQDZTMDPF", "U", "MY", "EADDK", "FA" and "FQXX", but then we will finally get to a three letter word - "KAG".

Now Python will follow the path indented under the "if len(curr_word) == 3:" line.

    three_letter_words.append(curr_word)

The word append is a 'method' of the list 'three_letter_words' and means add whatever is in the brackets after it (in this case our curr_word) as an element to the end of the list 'three_letter_words'. In this case, this is the end of an empty list so will in fact become the first item in the list. three_letter_words at this point therefore is represented as ["KAG"].

Now Python will carry on through the whole loop, adding every three letter word it comes across, and resetting curr_word back to "" every time it comes to a break in a word - i.e. a 'space' or a punctuation mark (with punctuation marks also not in 'ALPHABET').
